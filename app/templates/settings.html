Dispatcher setid ranges (default for new nodes)
Each trunk and gateway group gets its own dispatcher setid, allocated independently of its own database id (so deleted trunks' setids are recycled, and the two ranges can never collide regardless of how many trunks have ever existed). These are the defaults a new node inherits at registration -- changing them here doesn't affect any already-registered node; adjust an individual node's ranges from its own Node Settings page instead. The gateway group range must start after the trunk range ends.
EVS Codec

Off by default. Every node attempts to build EVS support for rtpengine automatically (best-effort -- a build failure on any given node doesn't stop that node's install, it just runs without EVS available). This toggle is separate from whether it's built: it controls whether EVS actually appears as something admins can select in Media Profiles at all.

Worth knowing before enabling: EVS is a patent-encumbered codec, jointly developed by Fraunhofer, JVCKenwood, NTT, NTT Docomo, Panasonic, and Ericsson. The 3GPP reference implementation being publicly downloadable (which is how each node builds support for it) is for standards-conformance and interoperability development -- it is not the same thing as a royalty-free grant to transcode real production traffic. Whether your deployment needs a patent license to actually use EVS commercially is a legal question this platform can't answer for you.

Log & Data Retention (Manager)
Audit/sync/ban logs are database tables, pruned daily (03:17) by a cron job. App log files (this Manager's own sip-platform.log and cron job logs) use a logrotate config applied immediately on save. Per-node log files (sync-routing.log, push-stats.log) are configured on each Node's own Settings page instead.
