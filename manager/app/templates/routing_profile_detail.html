LCR Rules
Each row is one carrier's cost-rank for a called-number prefix. Add multiple rows sharing the same prefix to give the lcr engine several carriers to try in order -- lower priority number tried first (0 = highest priority), weight is a probabilistic tie-break among rows sharing the same priority. If the first carrier's call fails (5xx/408), Kamailio automatically tries the next one live, in-call -- this is the actual reason to use this engine over a Prefix plan's LCR group field, which only ever resolves the cheapest option once at sync time.

Arithmetic rules
Rules are evaluated in order -- the first one whose conditions match wins, and its destination is used. Up to 5 rules per plan, up to 5 conditions per rule (for more, chain plans via Fallback plan instead). Match all: every condition must be true. Match any: at least one must be true. Chain: conditions combine strictly left-to-right using each condition's own and/or (no standard precedence -- "A or B and C" evaluates as "(A or B) and C", not "A or (B and C)").
