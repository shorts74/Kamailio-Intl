Selected Algorithm Reference
Round-robin (default) -- cycles through member trunks in order, one at a time. No trunk-level fields needed. Fair distribution, no special config required.
Random -- picks a random member trunk on each call. No trunk-level fields needed.
Priority (serial failover) -- always tries the lowest-numbered Priority trunk first (set on each trunk's own edit page); if it fails, automatically tries the next-lowest. This is genuine serial failover, not simultaneous ringing.
Weight-based -- distributes calls by percentage using each trunk's Weight field (1-100). The weights across all members should sum to ≤100; if under 100, the last trunk absorbs the remainder. Example: two trunks weighted 70/30 send roughly 70% and 30% of calls respectively.
Relative weight -- similar to Weight-based, but recalculates proportionally if a member goes down (e.g. two trunks at rweight 1/1 split 50/50; if one fails, the survivor gets 100% automatically, no manual rebalancing). Set each trunk's Relative weight field. Optionally enable Congestion control per trunk to have Kamailio's measured ping latency reduce that trunk's effective weight under load.
Parallel forking -- rings every member trunk simultaneously; whichever answers first is connected, the rest are automatically canceled. No trunk-level fields needed. Trade-off worth knowing: no serial failover and no per-trunk health tracking are possible with this algorithm -- a failure means every member failed to answer, not "try the next one," since there is no next one.
Call load -- routes each new call to whichever member currently has the fewest active calls. Requires no per-trunk fields, but needs the node-wide dispatcher / ds_hash_size setting (Node Settings) to be greater than 0 -- ask before relying on this if unsure it's set.
Latency-optimized -- round-robins while favoring higher-Priority trunks, automatically adjusting effective priority down as measured ping latency increases. Requires the node-wide dispatcher / ds_ping_latency_stats setting (Node Settings) to be enabled -- otherwise this behaves like plain priority-based round-robin with no latency adjustment.
Round-robin / priority hybrid -- round-robins normally if every member shares the same Priority value; if priorities differ, falls back to serial failover by priority instead (same as algorithm 8).
